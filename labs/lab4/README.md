## Аналіз завдань

### Завдання 1

В обох частинах формули потрібен косинус. Тому достатньо однієї функції `cosSum`, яку викликаємо з різними аргументами.

Ряд для косинуса має вигляд:

```text
cos(t) = 1 - t²/2! + t⁴/4! - t⁶/6! + ...
```

Перший член дорівнює `1`. Наступні члени рахуємо так:

```text
a₀ = 1
aₖ = -aₖ₋₁ · t · t / ((2k - 1) · 2k), k = 1, 2, ...
```

Тобто беремо попередній член, множимо на `-t*t` і ділимо на два наступні множники. Функції для степеня та факторіала не потрібні.

Перед додаванням перевіряємо новий член: якщо його модуль не більший за задану точність, закінчуємо обчислення. Косинус періодичний, тому спочатку зменшуємо його аргумент до проміжку від `-π` до `π` за допомогою `remainder`. Так ряд швидше сходиться. На цьому проміжку відкинутий малий член дає оцінку залишку ряду.

Для кожного окремого косинуса використовуємо `eps / 10`. Це дає запас точності, оскільки потім результати множаться або діляться. Для надзвичайно великих аргументів додатково впливає точність самого типу `double` та зведення аргумента за періодом.

Після введення даних програма проходить значення `x` від початку до кінця із заданим кроком. Якщо крок не потрапляє точно у кінцеве значення, останнім буде значення сітки, яке ще не перевищує кінець.

- Якщо `x < -1`, функція за умовою не визначена.
- Якщо `-1 ≤ x ≤ 0`, ділимо `cosSum(x/2)` на `cosSum(x*x)`. Знаменник тут не дорівнює нулю, бо `x*x` лежить від `0` до `1`.
- Якщо `x > 0`, множимо `cosSum(x/2)` саме на себе та на `cosSum(2*x)`.

Стандартний результат рахуємо за тими самими формулами, але через бібліотечну функцію `cos`.

За буквальним формулюванням умови похибку рахуємо як **різницю абсолютних значень**:

```text
error = |y| - |standard|
```

Тому в таблиці похибка може бути від'ємною. Це саме різниця модулів, а не модуль різниці `|y - standard|`.

### Завдання 2

Дріб зручно рахувати знизу вгору. Змінна `f` зберігає вже обчислену внутрішню частину дробу.

Спочатку `f = 0`. У циклі змінюємо `i` від `n` до `1` та виконуємо:

```text
f = 1 / (2*i + 1 + f)
```

На першому кроці отримуємо `1 / (2n + 1)`. Потім підставляємо це значення у попередній знаменник. Наприкінці додаємо зовнішню одиницю: `result = 1 + f`.

Наприклад, для `n = 2`:

```text
f = 1/5
f = 1/(3 + 1/5) = 5/16
result = 1 + 5/16 = 1.3125
```

## Приклади для перевірки

Для завдання 1 можна ввести:

```text
-1 1
0.5
0.000001
```

Приблизні стандартні значення:

| x | y |
|---:|---:|
| -1 | 1.62424360 |
| -0.5 | 1.00000000 |
| 0 | 1.00000000 |
| 0.5 | 0.50723109 |
| 1 | -0.32049597 |

Для `x < -1` має з'явитися повідомлення `function is not defined`. Нульовий або від'ємний крок, неправильні межі та точність поза дозволеним діапазоном мають спричинити повідомлення про помилку.

Для завдання 2:

| n | Значення дробу |
|---:|---:|
| 1 | 1.3333333333 |
| 2 | 1.3125000000 |
| 3 | 1.3130434783 |

Для `n = 0`, від'ємного або дробового `n` програма повідомляє про помилку.

Команди з папки `labs/lab4`, якщо встановлений компілятор `g++`:

```powershell
g++ -pipe -std=c++17 -Wall -Wextra -c task1.cpp -o task1.o
g++ task1.o -o task1.exe
g++ -pipe -std=c++17 -Wall -Wextra -c task2.cpp -o task2.o
g++ task2.o -o task2.exe
./task1.exe
./task2.exe
```

Компіляцію та збирання розділено на два кроки, щоб MinGW не створював тимчасові об'єктні файли у шляху з українськими літерами. Файли `.o` є проміжними й після збирання більше не потрібні.
